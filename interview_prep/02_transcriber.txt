QUESTION 1: ARCHITECTURE & COST/PRIVACY TRADE-OFFS
Q: "Why run Whisper locally instead of calling the OpenAI Whisper API?"

Interviewer is testing: Your ability to weigh cost, privacy, latency, and
   operational trade-offs.

IDEAL ANSWER:
"It is an engineering trade-off across three dimensions:
1. Data Privacy & Compliance: Many meetings contain confidential corporate IP
   or personal data. Running Whisper locally keeps all audio and transcripts
   strictly on-premise without third-party exposure.
2. Cost at Scale: OpenAI charges $0.006 per minute. For a platform processing
   thousands of hours of video monthly, cloud API bills accumulate rapidly.
   A local open-source model running on dedicated GPUs incurs zero per-minute
   API fees.
3. Offline Availability: Local models run independently of external SaaS
   outages or rate limits.
The trade-off is computational cost: local models require local hardware
(RAM/GPU) compared to lightweight cloud API calls."


--------------------------------------------------------------------------------
QUESTION 2: DEEP LEARNING / MODEL ARCHITECTURE
Q: "Can you briefly explain how Whisper works under the hood?"

Interviewer is testing: Do you understand the GenAI/deep learning model you are
   deploying?

IDEAL ANSWER:
"Whisper is an Encoder-Decoder Transformer model trained on 680,000 hours of
weakly-supervised multilingual web audio.
1. Feature Extraction: Audio (16kHz mono) is converted into 80-channel
   log-magnitude Mel Spectrograms in 30-second windows.
2. Transformer Encoder: Encodes spectrogram frames into latent representations.
3. Transformer Decoder: An autoregressive decoder predicts text tokens
   conditioned on the encoder outputs and previous tokens.
4. Multitask Tokens: Special prompt tokens instruct the model whether to
   transcribe (same language), translate (into English), predict timestamps,
   or identify language."


--------------------------------------------------------------------------------
QUESTION 3: INDIAN REGIONAL & CODE-SWITCHING LANGUAGES
Q: "Whisper supports Hindi. Why did you integrate Sarvam AI for Hinglish
   instead of using Whisper?"

Interviewer is testing: Knowledge of domain-specific model strengths, Indian
   NLP, and code-mixing.

IDEAL ANSWER:
"While Whisper is multilingual, it struggles with:
1. Indian Accents & Colloquialisms: Indian English and code-mixed speech
   (Hindi words embedded in English grammar or vice-versa) result in high
   Word Error Rate (WER) in Whisper.
2. Code-Switching (Hinglish): People in corporate meetings rarely speak pure
   formal Hindi; they speak 'Hinglish'. Whisper often attempts to transliterate
   Hinglish into Devanagari script phonetically or drops English terms.
3. Sarvam AI's Saaras Model: Specifically trained on vast Indian conversational
   datasets. It excels at Indian acoustic models, handles code-mixing natively,
   and transcribes Hindi/Hinglish speech directly into clean, coherent English
   text in a single step."


--------------------------------------------------------------------------------
QUESTION 4: API DESIGN & CONSTRAINTS
Q: "Why did you slice audio into 25-second pieces for Sarvam AI? Why not send
   the full 10-minute chunk?"

Interviewer is testing: Handling external API contracts, timeouts, and payload
   limits.

IDEAL ANSWER:
"Sarvam AI's synchronous `/speech-to-text-translate` endpoint has a strict
hard limit: it only accepts audio payloads <= 30 seconds.
1. We divide the 10-minute audio into 25-second slices, leaving a 5-second
   safety buffer to avoid edge-boundary rejections.
2. Each slice is dispatched sequentially (or concurrently), and the returned
   transcripts are stitched together.
3. To prevent disk bloat, each 25-second slice WAV is cleaned up immediately
   inside a `finally` block."


--------------------------------------------------------------------------------
QUESTION 5: SOFTWARE ENGINEERING DESIGN PATTERNS
Q: "What design pattern did you use in `load_model()` and why does it matter?"

Interviewer is testing: Python software design patterns and resource efficiency.

IDEAL ANSWER:
"We used the **Singleton / Lazy-Loading Pattern**.
Whisper model weights (`small` model is ~500MB, `medium` is ~1.5GB) take several
seconds and significant memory to load.
By declaring a module-level `_model = None` and only loading it inside
`if _model is None:`, we guarantee:
- The model weights are loaded into memory exactly once per application
  lifecycle.
- Memory is not allocated at startup if the user only uses Sarvam AI.
- Subsequent chunk transcriptions reuse the cached model instance in RAM."
